> **프론트 계약이 하나 바뀝니다**(2장). 운영 DB 반영은 3장을 직접 실행해 주세요.

## 0. 세 줄 요약

- 원인 지목(`ItineraryService.recommend()`)은 정확했습니다. 다만 **62편이 전부 시드 부족은 아니었습니다.**
  그중 22편은 이미 장소를 갖고 있었고 `POST /itineraries/route` 는 정상 동작 중이었습니다 —
  같은 데이터를 보는 두 엔드포인트가 다르게 답하고 있었습니다.
- `recommend()` 가 `ContentAnchorResolver` 를 쓰도록 고쳤습니다. **코드만으로 22편 해소.**
- 시드 47행을 검수·적용하면 **5편 추가 해소**. 합쳐서 62 → 35 입니다.

## 1. 왜 62편이었나

`recommend()` 는 `content_place` 만 직접 읽었습니다. 반면 `RoutePlanner` 는
`ContentAnchorResolver` 를 써서 **인물 체인**(`content_person → place_person`)까지 봅니다.

| 경로 | 작품 수 |
| --- | ---: |
| `content_place` (승인 매핑) | 26 |
| 인물 체인만 있음 | 22 |
| 둘 다 없음 | 40 |
| **합계(공개 작품)** | **88** |

`recommend()` 는 26편만 보고 62편에 404를 냈습니다. 티켓 예시 4개 중 간신·명량·왕의 남자
3개가 **인물 체인으로 이미 장소가 있던** 작품입니다.

## 2. ⚠️ 프론트 계약 변경 — `GET /api/itineraries/recommend`

### 2-1. 장소가 없어도 **200** 으로 내려갑니다

티켓 4번 요청대로입니다. 404 는 서버 오류와 구분이 안 돼 "추천 일정을 불러오지 못했어요" 로
뭉뚱그려졌습니다.

```jsonc
// 장소가 아직 없는 작품 — 이제 200
{
  "content_id": 18302,
  "content_title": "취화선",
  "anchor_source": "NONE",
  "slots": []
}
```

`anchor_source: "NONE"` + 빈 `slots` 이면 **"아직 준비 중"** 을 띄우면 됩니다.
**404 는 이제 "콘텐츠 자체가 없음" 일 때만** 납니다.

### 2-2. `anchor_source` 필드가 추가됐습니다

| 값 | 뜻 | 화면에서 |
| --- | --- | --- |
| `CONTENT_PLACE` | 승인된 작품–장소 매핑 | "작품의 장소"라고 써도 되는 유일한 등급 |
| `PERSON_CHAIN` | 작품에 나오는 실존 인물의 연고지 | **"촬영지"라고 쓰면 안 됩니다.** "작품 속 인물과 연결된 곳" 정도로 |
| `NONE` | 아직 없음 (`slots` 비어 있음) | "아직 준비 중" |

`POST /itineraries/route` 가 이미 같은 이름으로 같은 값을 주고 있어 표기를 맞췄습니다.

## 3. 운영 DB 반영 (직접 실행 필요)

제 권한으로는 운영 DB 쓰기가 차단됩니다. SQL 은 만들어 뒀고 **멱등**이라 여러 번 실행해도
같은 결과입니다.

```powershell
$OutputEncoding=[Text.UTF8Encoding]::new($false); [Console]::OutputEncoding=[Text.UTF8Encoding]::new($false)
Get-Content scripts\load-seed-content-places.sql -Encoding UTF8 -Raw |
  ssh -i "$env:USERPROFILE\.ssh\itda-key.pem" ubuntu@54.116.7.199 `
    "docker exec -i -e PGPASSWORD=<비번> itda-postgres psql -U itda -d itda -v ON_ERROR_STOP=1"
```

`BEGIN … ROLLBACK` 으로 운영에서 미리 돌려 **오류 0건**을 확인했습니다.

## 5. 생성기 버그 하나 고쳤습니다

`seed-content-places.ps1` 의 `build-sql` 이 만들던 가드가 이랬습니다:

```sql
AND EXISTS (SELECT 1 FROM content c WHERE c.content_id = 113464)
```

`content` 테이블의 PK 는 `content_id` 가 아니라 **`id`** 입니다. 그대로 실행하면
`column c.content_id does not exist` 로 **전체 스크립트가 죽습니다.** `c.id` 로 고쳤습니다.
