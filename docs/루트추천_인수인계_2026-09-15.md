## 추천 설계안 — 초기 제안, 사용자 확정 전

### 1. 작품 관련 명소 확보

1. 승인된 content_place를 우선 사용한다.
2. 작품→실존 인물→장소 연결에서 역사 현장·기념관 후보를 확보한다. 인물 일치만으로 작품 관련성을 자동 승인하지 않는다.
3. 부족하면 작품명/사건명/인물명으로 TourAPI 및 공식 관광·문화기관 근거를 찾아 보충한다.
4. 작품과의 관계를 HISTORICAL / FILMING / EXHIBIT로 기록하고 출처 URL과 판단 근거를 남긴다. 시대가 같다는 이유만으로 관련 명소로 간주하지 않는다.
5. 좌표·방문 가능성·중복을 확인한다. 여행코스 자체, 숙박, 쇼핑, 음식점은 여행지 3곳 후보에서 제외한다.
6. 후보 발견·근거 판단은 배치로 실행하고 결과를 저장한다. 사용자 요청 때마다 LLM 검색하지 않는다.

### 2. 일반 명소 보충과 순서

- 가까운 관련 명소 2곳이 있으면 일반 명소 1곳, 하나만 쓸 수 있으면 일반 명소 2곳.
- 멀리 떨어진 관련 명소 2곳을 억지로 연결하지 않는다. 지역별로 다른 코스를 만들거나 가장 좋은 지역 하나를 선택한다.
- 일반 명소는 관련 명소 주변 5km부터 검색하고 10km, 최대 15km로 확대한다.
- TourAPI 관광지·문화시설 중심으로 좌표·방문 가능성·이미지·소개를 확인하고, 적은 우회거리와 서로 다른 경험(유적/공원/전망 등)을 우선한다.
- 사진 존재를 인기도로 해석하지 않는다. 신뢰할 인기 지표가 없으면 '인기순'이라 표시하지 않는다.
- 일반 명소에는 작품 관련 문구를 붙이지 않는다. 촬영지/역사 현장/주변 명소를 구분한다.
- 후보 3곳의 6개 방문 순서를 비교해 짧은 동선과 영업시간에 맞는 조합을 고른다.
- 3곳을 채우지 못하면 ROUTE_INCOMPLETE로 보류하며 작품 관련 명소 0곳과 구분한다.

### 3. 거리 초기값

아래 수치는 서비스 설계 제안이며 실제 표본 코스 검증 전 잠정값이다.

| 기준 | 제안 |
| --- | --- |
| 인접 여행지 직선거리 | 15km 이내 우선, 25km 상한 |
| 여행지 3곳 사이 두 구간 직선거리 합 | 40km 이하 |
| 실제 차량 경로 검증 가능 시 | 구간당 40분 이하, 명소 사이 이동 합 80분 이하 |
| 식당·카페 타원 추가 우회거리 | 기본 3km, 후보 부족 시 5km |

- 실제 도로 거리/시간은 별도다. 직선 60km를 차량 1시간으로 환산하지 않는다.
- 카카오모빌리티 자동차 길찾기 응답의 distance/duration으로 후보 최종 조합을 검증하고 캐시하는 방법 권장: https://developers.kakaomobility.com/guide/navi-api/directions
- 길찾기 미연동이면 직선 기준임을 유지하고 차량 소요시간을 보장하지 않는다. 바다·산·강으로 단절된 조합은 추가 검수한다.
- 식당·카페가 각각 타원을 통과해도 연속 방문 시 전체 우회가 커질 수 있다. 사용자가 고른 뒤 A→식당→카페→B 실제 전체 동선을 재계산해야 한다.
- 3km는 타원 반경이 아니라 A→B에 비해 추가되는 직선 이동거리다.
- 기존 저녁 뒤 마지막 명소 템플릿은 폐장 시간과 충돌할 수 있다. 운영시간 검증을 통과한 장소로 구성하거나 슬롯 순서 재검토 필요.

### 4. 작품 숨김

- 수집 미완료/상류 API 실패를 '관련 명소 없음'으로 확정하지 않는다.
- 배치 완료·근거 검토 후 0곳으로 확정된 작품만 NO_RELATED_PLACE로 기록하고 숨긴다.
- 기록: content_id, title, 확인한 검색 경로, 결과 수, 사유, checked_at, 재검수 상태.
- 권장: 영화 ID/제목에 null을 넣는 대신 route_status(예: PENDING/READY/NO_RELATED_PLACE/ROUTE_INCOMPLETE)를 별도로 관리. 기존 콘텐츠 분류 status와 구분한다.
- 전체 노출은 기존 공개 조건 + route READY로 통일하는 안을 검토. 본문 목록·검색·시대별·인물별·상세 직접 접근에서 모두 적용해야 한다.
- route 응답 null 표현이 프론트 계약상 필요하다면 JSON 응답에서 표현한다. 적용 필드/응답 계약은 구현 전에 확정할 것.
