| 작품 관련 명소 | 배치 |
| --- | --- |
| 0곳 | 루트를 만들지 않고 숨긴다 |
| 1곳 | 관련 1 + 일반 2 |

- 상수는 `RoutePlanner.MAX_RELATED_SPOTS = 2`.

  관련/일반 여부는 순서에 영향을 주지 않는다. `recommend_order` 는 더 이상 순서 기준이 아니다.

## 소스 역할 분담

관광공사 TourAPI 활용이 프로젝트 전제이므로 아래 순서를 코드에 고정했다.

| 용도 | 1순위 | 2순위 |
| --- | --- | --- |
| 일반 명소 | TourAPI 관광지(12) + 문화시설(14), 5→10→15km | 없음 (TourAPI 전용) |
| 앵커 실재 검증 | TourAPI `searchKeyword2` | 카카오 키워드 검색 |
| 식당·카페 | TourAPI 음식점(39) | 카카오 FD6/CE7 |
| 자동차 경로·소요시간 | 카카오모빌리티 | — |
| 지도 표시 | 카카오맵 SDK (프론트) | — |

TourAPI 의 `mapx`/`mapy` 는 WGS84 라 카카오맵·카카오모빌리티에 좌표 변환 없이 그대로 넣는다.

## 커버리지 실측 (공개 작품 93편)

| 경로 | 편수 |
| --- | ---: |
| 인물 체인(content_person→place_person) | 22 |
| LLM 발굴 드라이런으로 확보 | 28 |
| **합계** | **50 (54%)** |
| 관련 명소 0곳 → 숨김 대상 | 43 |

- 43편 중 41편은 국내에 관련 장소가 실제로 없다(`모가디슈` 소말리아, `안시성` 중국, `봉이 김선달` 평양, SF·순수 창작 사극).
  나머지 2편(`연평해전`, `변호인`)은 검색 키워드를 못 맞춘 경우다.
- 앵커 출처는 TourAPI 30건 / 카카오 11건 — 관광공사 비중 73%.
- 인물 체인 22편 중 앵커가 25km 안에 모이는 것은 8편이고 14편은 흩어져 있다.
  가장 심한 것은 이순신 소재 작품들로 현충사(아산)와 한산도가 265km 떨어져 있다.
  `ContentAnchorResolver.densestCluster` 가 가장 많이 모인 지역만 남긴다.

## 실호출로 발견해 고친 버그 5개

1. **표기 차이로 0건** — `제주4.3평화공원` 은 0건, `제주4·3평화공원`(가운뎃점)은 잡힌다.
   → 검색어 변형(가운뎃점·공백)을 순차 시도하고 contentTypeId 를 12→14→전체로 넓힌다.
2. **부분일치 오탐** — `이화장`(이승만 사저) 검색에 `한국자이화장품`(강서구 화장품 가게)이 걸렸다.
   → 결과 이름이 검색어로 시작하거나 끝나거나 여는 괄호 뒤에 와야 통과.
   TourAPI 는 `서울 운현궁` 처럼 지역을 앞에 붙여 등록하므로 접두만 보면 정상 결과를 버린다.
3. **동명 장소** — `자유공원` 은 안양시 것이, `전쟁기념관` 은 창녕 박진전쟁기념관이 1순위로 나온다.
   → `DiscoveredPlace.region` 을 LLM 에게 받아 결과 주소와 대조한다.
   관광API 주소는 `경상남도`, LLM 은 `경남` 이라 약칭 매핑이 필요하다.
   이름 검사만으로는 `박진전쟁기념관` 을 못 거르므로 지역 검사와 반드시 함께 써야 한다.
4. **카카오 폴백 조건 오류** — "TourAPI 0건일 때만" 폴백해서, 결과는 있으나 전부 검증 탈락한
   경우(`이화장`)에 폴백을 건너뛰었다. → "검증 통과가 없을 때" 로 바꾸니 26편 → 28편.
5. **카카오 키 충돌** — `application.yml` 의 `kakao.client-id` 가 `KAKAO_REST_API_KEY` 를 쓴다.
   지도용 키로 그 변수를 덮으면 카카오 로그인이 다른 앱으로 넘어가 깨진다.
   → 지도·검색·길찾기는 `KAKAO_MAP_REST_KEY` 로 분리했다.

## 카카오 앱 설정

- 로그인 앱(`itda`)은 카카오맵 제품이 꺼져 있어 로컬 API 가
  `403 NotAuthorizedError: App(itda) disabled OPEN_MAP_AND_LOCAL service` 를 돌려준다.
- 카카오맵이 활성화된 별도 앱의 REST 키로 검색·길찾기를 확인했다(모두 HTTP 200).
- **GitHub Secrets 에 `KAKAO_MAP_REST_KEY` 를 등록해야 한다.** 없으면 배포 후 지도 관련
  조회가 예외 없이 빈 결과만 돌려주므로 조용히 실패한다.

## 남은 작업

1. 운영 DB 접속과 `ANTHROPIC_API_KEY` 확보.
2. `POST /api/admin/route/discover-anchors?only_missing=true&max_contents=5` 로 소량 먼저 실행하고
   결과를 사람이 검수한다. 한 번에 전체를 밀지 않는다.
3. 검수 후 전체 배치 → `POST /api/itineraries/route` 로 실제 루트 확인.
4. 관련 명소 0곳 작품의 숨김 처리를 목록·검색·시대별·인물별·상세 모든 경로에 적용.
5. 프론트에 전달할 응답 변경: `anchor_source`, `travel_distance_meters`, `travel_duration_seconds`,
   `road_verified`, `within_time_limits`, 후보의 `source`, 슬롯의 `GENERAL` 구분.
