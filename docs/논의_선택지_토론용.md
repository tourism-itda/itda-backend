## 논의 1 — `relation_type`(역사현장/촬영지/일반명소)을 누가 매기나

**왜 문제냐:** 후보 63건을 이름으로 자동 분류해봤더니 **촬영지 0건 / 역사현장 31건 / 일반명소 37건**이 나왔는데, **'일반명소' 안에 진짜 역사현장이 잔뜩 섞여 있습니다.**

```
제승당 · 한산도 · 울돌목 · 개태사 · 삼전도비 · 자유공원(인천) · 월미도
   → 전부 역사 현장인데 이름에 '기념관/유적' 이 없어서 누락
고구려대장간마을
   → 실제로는 드라마 세트장(= 촬영지)인데 '일반명소' 로 감
```

원인은 CSV 의 `category` 값이 `관광지(47) / 문화시설(15) / 축제(1)` 세 개뿐이라서입니다.
**TourAPI 가 주는 세부분류 `cat3` 를 스크립트가 저장하지 않고 있습니다.**

| 안 | 내용 | 고르면 | 장점 | 단점 | 작업량 |
| --- | --- | --- | --- | --- | --- |
| **A** | 검수자가 CSV `relation_type` 열에 손으로 | 63건 × 판단 1회 추가 | 정확 | 검수 시간 늘어남. 확장 시 계속 부담 | S (열 추가) |
| **B** ⭐ | **`cat3` 를 CSV에 담고 코드로 매핑** (`A02010700` 유적지→역사현장 등) | 자동 분류 시도 가능 | 공짜. 되면 확장도 공짜 | **검증 안 됨** — 설계문서에 *"cat3로 촬영지를 거를 수 없다"* 는 실측 기록 있음 | S (1줄) |
| **C** | LLM 이 이름+작품 보고 3지선다 | 「제승당」이 이순신 유적인 걸 앎 | 사람 판단에 가까움 | 비용. 환각(단 3지선다라 위험 낮음) | M |
| **D** | 지금은 안 매기고 출시 | 결정 2를 미룸 | 빠름 | **결정 2가 무의미해짐** | 0 |

**제 추천: B → 안 되면 A.**
cat3 컬럼 추가는 스크립트 1줄이라 **일단 담아보고 실제로 갈리는지 보면 됩니다.** 안 갈려도 A로 가면 되고, 어차피 검수는 하니까 손실이 없습니다.
❓ **물어보고 싶은 것:** cat3가 안 갈릴 경우, A(수동)와 C(LLM) 중 어느 쪽이 나을까요?

## 논의 2 — 지역을 어떻게 묶나 ★ 숫자 차이가 제일 큼

**왜 문제냐:** 「안시성」은 후보가 12건으로 제일 많은데 **시도로 묶으면 4개로 쪼개져 코스가 하나도 안 나옵니다.**
그런데 **아차산성(서울)과 고구려대장간마을(경기 구리)은 실제로 600m 거리**입니다. 행정구역만 다릅니다.

네 가지 기준으로 전부 계산해봤습니다.

| 기준 | **코스 수** | 안시성 | 노량 | 남한산성 | 비고 |
| --- | --- | --- | --- | --- | --- |
| **A. 시도(市道) 경계** | 8개 | ❌ 못 만듦 | ✅ 3곳 | 5곳 | 600m 거리가 갈라짐 |
| **B. 거리 40km** | 8개 | ✅ 3곳 | ❌ 빠짐(50.3km) | **6곳** | 안시성 살고 노량 죽음 |
| **C. 거리 60km (차로 1시간)** ⭐ | **9개** | ✅ | ✅ | **6곳** | **둘 다 살아남음** |
| D. 사용자가 지역 먼저 선택 | — | — | — | — | 진입 단계 추가 |

**60km 기준으로 나오는 코스 9개**

```
인천            11곳  (최대 21.3km)
남한산성          6곳  (9.4km)   ← 시도 기준이면 5곳. 서울 앵커 1곳이 합류
인천상륙작전        5곳  (8.0km)
명량             4곳  (2.0km)
서부전선           4곳  (4.0km)
지슬             4곳  (14.0km)
한산: 용의 출현      4곳  (7.3km)
노량: 죽음의 바다     3곳  (50.3km)  ← 통영 충렬사 ↔ 남해 관음포
안시성            3곳  (0.8km)   ← 시도 기준이면 0개
```

**제 추천: C (60km 클러스터).**
시도 경계는 여행자한테 아무 의미가 없습니다. 차로 1시간이면 하루 코스로 납득 가능한 범위고, 계산해보니 **코스가 8개 → 9개로 늘고 남한산성도 5곳 → 6곳으로 좋아집니다.**

❓ **물어보고 싶은 것:** 「노량」의 통영 ↔ 남해 **50km(차로 1시간 남짓)를 하루 코스로 볼 수 있는지.** 이게 60km냐 40km냐를 가릅니다. 여기가 유일하게 애매합니다.

## 논의 3 — 차량 기준 상수값을 언제 어떻게 손볼까

**왜 문제냐:** 결정 4(차로 이동)를 하면 현재 값들이 안 맞습니다.

| 값 | 현재 | 무슨 기준이었나 |
| --- | --- | --- |
| 이동 속도 | **25 km/h** | 도심 혼잡 기준 → 「인천」(21km) 이동에 50분 잡힘 |
| 허용 우회거리 (기본) | **3 km** | 도보 기준 |
| 허용 우회거리 (최대) | 20 km | |
| 체류시간 | 120/90/60분 | 설정 주석에 *"팀 합의 후 재조정 가능"* |

| 안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A** ⭐ | **일단 현행 유지** → 코스 9개 뽑아서 타임라인 보고 정함 | 감으로 안 정함 | 결정이 한 번 미뤄짐 |
| **B** | 지금 차량 기준으로 일괄 상향 (50km/h · 기본 10km · 최대 30km) | 바로 말 되는 일정 | 숫자 근거가 감 |
| **C** | 사용자가 이동수단(도보/차량) 고르면 분기 | 제일 정확 | 작업량 큼. 프론트도 바뀜 |

**제 추천: A.**
지금 정해봐야 근거가 없습니다. **코스 9개를 실제로 뽑으면 "이건 말이 안 되네"가 바로 보입니다.** 그때 B로 가면 됩니다.

## 논의 4 — 앵커가 1~2곳뿐인 작품들

60km 기준으로도 **3곳 이상 모이는 건 9개, 나머지 15개 조합은 1~2곳**입니다. (평양성·하얼빈·태조 왕건·봉오동 전투·장사리·마이웨이 등)

| 안 | 내용 | 고르면 | 장점 | 단점 |
| --- | --- | --- | --- | --- |
| A | **숨김** (3곳 미만 제외) | 20편 중 **9개 코스만** 노출 | 품질 보장 | 콘텐츠 목록이 휑함 |
| B | **반나절 코스로 노출** — `DayTemplate` 이 1~2곳도 이미 지원 | 커버리지 유지 | 정직하면 문제없음 | 기대 대비 빈약 |
| C | 인근·동시대 앵커로 **채워서** 3곳 | 항상 완성형 | 작품 관련성 희석 |
| **D** ⭐ | **키워드부터 보강** — `seed-keywords.csv`(현재 55건) 확장해서 앵커를 더 찾음 | 근본 해결 | 사람이 키워드를 더 써야 함 |

**제 추천: D 먼저, 그래도 안 되면 B.**
「하얼빈」이 앵커 1곳(안중근의사기념관)인 건 **키워드를 하나만 넣어서**입니다. `하얼빈 의거`·`장충단` 같은 걸 더 넣으면 늘어납니다. 구조를 바꾸기 전에 **입력부터 채우는 게** 싸게 먹힙니다.

> 참고: **「무사」는 허구 서사**라 시대 범위(고려)로는 안 걸러지는데, 앵커 2건이 전부 오매칭(`"무사"` → **충무사** = 이순신 사당)이라 검수에서 탈락합니다. → 결과적으로 앵커 0건이 되어 이 논의로 넘어옵니다.

## 논의 5 — 검수 비용을 어떻게 감당하나

**지금 A등급 0건 / B등급 전부.** 자동 통과가 하나도 없어서 63건을 전부 사람이 봐야 합니다.
20편에 63건이면 **100편이면 300건 이상**입니다.

| 안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| A | 전수 수동 계속 | 품질 최상 | 확장 불가 |
| B | 자동 승인 규칙 확대 (검색어가 장소명에 완전 포함 + 좌표 + 이미지) | 확장 가능 | 「무사」→충무사 같은 오매칭이 통과할 위험 |
| C | LLM 1차 + 사람 샘플 | 확장 + 품질 절충 | 비용. 샘플 비율 합의 필요 |
| **D** ⭐ | **이번 63건은 수동, 콘텐츠 늘릴 때 C로** | 지금 당장 안 막힘 | 나중에 또 논의 |

**제 추천: D.**
63건은 **반나절이면 봅니다.** 지금 자동화를 설계하는 건 이른 최적화 같습니다. 콘텐츠를 100편으로 늘리기로 정해지는 순간 C를 하면 됩니다.

❓ **물어보고 싶은 것:** **콘텐츠를 몇 편까지 늘릴 계획인지.** 20편 유지면 D로 충분하고, 100편 이상이면 지금 C를 설계해야 합니다. 이게 정해지면 이 논의는 자동으로 풀립니다.

## 논의 6 — `content_place` 스키마 (박세현 님 결정)

논의 1(`relation_type`)을 구현하려면 컬럼이 필요한데, `ContentPlace` 가 박세현 님 소유 엔티티라 못 건드리고 있습니다.

```java
ContentPlace {
    content_id
    external_content_id
    relation_type    // ★ HISTORICAL | FILMING | GENERAL   ← 결정 2 구현에 필요
    grade            // A | B | C                          ← 노출 기준
    evidence         // 근거 (어떤 검색어로 잡혔나)
    recommend_order
}
```

| 안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| **A** ⭐ | `ContentPlace` 에 컬럼 3개 추가 | 단순. 조인 없음 | 남의 엔티티를 건드림 |
| B | 별도 테이블 `content_place_meta` 로 분리 | 소유 경계가 안 깨짐 | 조인 하나 늘어남 |
| C | DB 엔 안 넣고 CSV 에만 남김 (현행) | 아무것도 안 바꿔도 됨 | **결정 2를 런타임에 못 씀** |

**제 추천: A, 안 되면 B.** C는 결정 2를 사실상 포기하는 거라 빼는 게 맞다고 봅니다.
❓ **박세현 님:** 컬럼 추가가 부담되면 B로 갈게요. 어느 쪽이 편하신지만 알려주세요.
