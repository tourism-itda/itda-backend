# 루트 추천 API 변경사항 — 2026-09-17 (프론트 전달용)

> 기존 문서 `API_변경사항_프론트전달.md` 의 후속입니다. 여기는 **오늘 바뀐 것과 아직 없는 것**만 적습니다.
> 엔드포인트 경로·기본 흐름은 기존 문서를 그대로 따릅니다.

## 0. 세 줄 요약

- `POST /api/itineraries/route` 응답에 **필드 6개가 추가**됐습니다. 기존 필드는 그대로입니다.
- **"다른 코스 보기"(재생성)** 가 생겼습니다. 요청에 `exclude_place_ids` 를 누적해서 보내세요.
- 공개 작품 88편 중 **48편만 루트가 나옵니다.** 나머지 40편은 404 입니다. 목록에서 미리 거를 방법이 아직 없습니다 (아래 2-1 참고).

## 1. 바뀐 것

### 1-1. `POST /api/itineraries/route` — 응답 필드 추가

```jsonc
{
  "content_id": 407887,
  "content_title": "인천상륙작전",
  "region": "인천광역시",
  "spot_count": 3,
  "allowance_meters": 3000,

  "anchor_source": "CONTENT_PLACE",      // 신규
  "travel_distance_meters": 10221,       // 신규
  "travel_duration_seconds": 2220,       // 신규
  "road_verified": true,                 // 신규
  "within_time_limits": true,            // 신규

  "slots": [ /* ... */ ],
  "segments": [ /* ... */ ]
}
```

| 필드 | 뜻 | 화면에서 |
| --- | --- | --- |
| `anchor_source` | `CONTENT_PLACE` = 승인된 작품–장소 매핑 / `PERSON_CHAIN` = 작품에 나오는 실존 인물의 연고지 | **`PERSON_CHAIN` 이면 "촬영지"라고 쓰면 안 됩니다.** "작품 속 인물과 연결된 곳" 정도로 표기해 주세요 |
| `travel_distance_meters` | 명소 사이 **도로** 총거리 | 실측 못 했으면 필드가 아예 없습니다(`null` 은 응답에서 빠짐) |
| `travel_duration_seconds` | 명소 사이 **차량 이동시간만** | **관람·주차·식사 시간은 포함하지 않습니다.** "총 소요시간"으로 쓰면 거짓말이 됩니다 |
| `road_verified` | 카카오 길찾기로 실측했는가 | `false` 면 위 두 값이 없습니다. "이동시간 계산 불가" 정도로 표시 |
| `within_time_limits` | 구간 40분·합계 80분 이내인가 | `false` 면 "이동이 긴 코스" 안내 배지 정도 |

실측 현황: 48편 중 `road_verified` 43편, `within_time_limits` 42편.

### 1-2. 슬롯의 `filled_by` 에 `GENERAL` 추가

```jsonc
{ "visit_order": 3, "slot_type": "SPOT", "label": "촬영지",
  "place": { "name": "인천업사이클에코센터", "category": "관광지", ... },
  "filled_by": "GENERAL" }
```

| 값 | 뜻 |
| --- | --- |
| `USER` | 사용자가 `spot_place_ids` 로 지정 |
| `CURATED` | Claude 가 후보 중 선택 (`reason` 이 같이 옵니다) |
| `SCORED` | 점수 1등으로 선택 |
| **`GENERAL`** | **작품과 무관한 주변 일반 관광명소** |
| `EMPTY` | 빈 칸 (식당·카페) |

**`GENERAL` 칸에 작품 관련 문구를 붙이면 안 됩니다.** "영화 속 그곳" 같은 라벨이 붙으면 거짓 정보가 됩니다.

루트 구성 규칙이 확정됐습니다.

| 작품 관련 명소 | 배치 |
| --- | --- |
| 0곳 | 루트를 만들지 않음 (404) |
| 1곳 | 관련 1 + 일반 2 |
| 2곳 이상 | 관련 2 + 일반 1 (3곳 이상 있어도 2곳까지만) |

현재 48편 중 관련 2+일반 1 이 23편, 관련 1+일반 2 가 25편입니다.

**관련/일반 여부는 방문 순서에 영향을 주지 않습니다.** 순서는 동선만 보고 정하므로 일반 명소가 첫 칸에 올 수 있습니다.

### 1-3. 구간 후보에 `source` 추가

`GET /api/itineraries/route/candidates` 의 각 후보에 출처가 붙습니다.

```jsonc
{ "external_id": "2869760", "source": "TOUR_API", "name": "...", ... }
```

`TOUR_API`(한국관광공사) 또는 `KAKAO`. 관광공사 데이터 활용이 이 프로젝트의 전제라 비중을 확인할 수 있게 노출했습니다. 화면에 꼭 표시할 필요는 없습니다.

### 1-4. 신규 — 다른 코스 보기(재생성)

요청에 `exclude_place_ids` 를 추가했습니다.

```jsonc
POST /api/itineraries/route
{ "content_id": 133200,
  "exclude_place_ids": [12, 45, 78] }
```

**직전에 받은 루트의 명소 `place_id` 를 넘기면 그것을 빼고 다시 고릅니다.**

> **중요: 회차를 거듭할 때 누적해서 보내세요.** 직전 것만 보내면 A ↔ B 로 왔다갔다 합니다.

바뀌는 범위는 작품마다 다릅니다.

| 작품 관련 명소 수 | 작품 수 | 재생성 시 |
| ---: | ---: | --- |
| 3~4곳 | 18편 | 작품 관련 명소까지 바뀜 |
| 1~2곳 | 30편 | 관련 명소는 유지, **일반 명소만** 바뀜 |

실제 동작 (운영 데이터):

```
광해(관련 명소 4곳)
  1회차: 경복궁* → 민영환 자결터 → 창덕궁*
  2회차: 조계사 → 종묘* → 동대문 닭한마리 골목
  3회차: 창덕궁* → 경복궁* → 삼청공원
  4회차 이후: 주변 후보 고갈로 순환

스윙키즈(관련 명소 1곳)
  1회차: 거제포로수용소유적공원* → 옥산성지 → 반곡서원
  2회차: 문동폭포 → 거제포로수용소유적공원* → 사곡해수욕장
  3회차: 거제포로수용소유적공원* → 죽림해수욕장 → 구천댐
  (* = 작품 관련 명소)
```

후보가 고갈되면 제외를 무시하고 이전 조합을 다시 줍니다. **명소가 3곳보다 적어지는 일은 없습니다.** 같은 결과가 또 나오면 "더 볼 코스가 없습니다" 정도로 안내하시면 됩니다.

### 1-5. 장소 분류(`category`) 표기 변경

전에는 관광API 코드(`A02010800`)가 그대로 나갔습니다. 이제 `관광지` / `문화시설` / `음식점` / `카페` 같은 한국어 라벨입니다. 분류를 모르면 필드가 빠집니다.

## 2. 아직 없는 것 (프론트가 기대할 수 있으나 구현 안 됨)

### 2-1. ⚠️ 작품 숨김이 목록에 반영되지 않습니다 — 가장 큰 갭

- 관련 명소가 0곳인 **40편**은 `POST /route` 가 **404** 를 돌려줍니다.
- 그런데 `GET /api/contents` 목록에는 **그대로 나옵니다.** 프론트가 사전에 알 방법이 없습니다.
- 지금은 사용자가 작품을 누른 뒤에야 "루트를 만들 수 없습니다"를 보게 됩니다.

**임시 대응**: 404 를 에러가 아니라 정상 분기로 처리하고 "이 작품은 아직 코스가 준비되지 않았습니다" 를 보여주세요.

**서버가 해야 할 일**: 목록 응답에 `route_available` 같은 플래그를 넣거나, 아예 목록에서 제외하는 것. `route_status` 필드는 현재 코드에 존재하지 않습니다. 어느 쪽을 원하는지 알려주시면 반영하겠습니다.

### 2-2. 일반 명소만 골라 바꾸는 API 가 없습니다

- 식당·카페는 `GET /route/candidates` 로 후보를 받아 하나씩 고를 수 있습니다.
- **일반 명소(`filled_by: GENERAL`)는 그게 안 됩니다.** 루트 전체를 재생성하는 방법뿐입니다.
- `GET /api/places/alternative` 가 있긴 하나 `content_place` 기반이라 **작품 관련 명소에만** 동작합니다.

필요하면 `GET /route/spot-candidates` 를 추가할 수 있습니다. 재료(후보 목록)는 이미 서버가 갖고 있어서 노출만 하면 됩니다.

### 2-3. 방문 순서를 사용자가 바꿀 수 없습니다

서버가 동선 기준으로 정한 순서가 그대로 나갑니다. 드래그로 재정렬하는 UI 는 지금 지원 근거가 없습니다. (저장 후 `PATCH /api/itineraries/{id}` 로는 가능할 수 있으나 루트 미리보기 단계에서는 불가)

### 2-4. 도로 경로 좌표열(polyline)이 없습니다

- 응답에는 명소 **좌표와 거리·시간**만 있습니다.
- 지도에 도로를 따라가는 선을 그리려면 프론트가 카카오 길찾기를 직접 부르거나, 서버가 좌표열을 내려주도록 추가해야 합니다.
- **직선으로 이어 그리는 것은 가능**하며, 그 경우 "실제 경로가 아님"을 표시해 주세요.

### 2-5. 식당·카페를 고른 뒤 전체 동선이 재계산되지 않습니다

- 각 후보가 개별적으로 타원(허용거리) 조건을 통과했을 뿐입니다.
- 식당과 카페를 **둘 다 경유**하면 실제 총 이동은 더 늘어납니다. 그 값을 다시 계산하는 API 가 없습니다.
- `estimated_time` 은 빈 칸을 균등 분배한 근사치입니다.

### 2-6. 루트 결과 캐시가 없습니다

같은 작품을 여러 번 요청하면 매번 관광공사·카카오 API 를 호출합니다. 트래픽이 붙으면 쿼터 문제가 생깁니다. 프론트에서 **불필요한 중복 호출을 피해 주세요** (특히 허용거리 슬라이더는 디바운스 필요).

### 2-7. 운영시간이 순서에 반영되지 않습니다

- 방문 순서는 동선만 봅니다. 마지막 칸 도착이 폐장 이후일 수 있습니다.
- 하루 시작을 09:00 으로 당겨 완화했지만 근본 해결은 아닙니다.
- `place.opening_hours` / `night_open` 은 응답에 있으니 **화면에서 "운영시간 확인 필요" 안내**를 띄워 주시면 좋겠습니다.

### 2-8. 기존 미해결 항목 (이전 문서 5장에서 계속)

- `GET /api/itineraries/recommend`(No.27)와 `POST /api/itineraries/route` 가 **병존 중**입니다. 어느 화면에서 무엇을 쓸지 아직 정해지지 않았습니다.
- 신규 엔드포인트가 명세서 v4 에 없습니다.
- `POST /api/places/import` 가 인증 없이 열려 있습니다.

## 4. 테스트

로컬에서 바로 눌러 볼 수 있는 페이지를 넣어 뒀습니다.

```
python -m http.server 5173 --directory tools
http://localhost:5173/route-test.html
```

작품 선택 → 루트 생성 → 구간 후보 조회 → 선택까지 전부 됩니다. 포트 5173 은 CORS 허용 목록에 들어 있어 그대로 쓰시면 됩니다.
