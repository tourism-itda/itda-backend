## 2. 고친 것

### 2-1. 사진·설명이 전부 비어 있던 문제 🔴 근본 원인

`detailCommon2` 가 `firstimage` 와 `overview` 를 같이 주고 `TourApiClient.findDetail` 도 둘 다
읽어 오는데, **저장할 때 둘 다 버리고 있었다.**

- `place_image` 에 INSERT 하는 코드가 프로젝트에 **하나도 없었다**
- `Place.ofTourApi` 에 description 파라미터가 **아예 없었다**

예: `왜고개`(contentId 2758125)는 관광API 에 사진도 있고 239자 설명도 있는데 DB 는 양쪽 다 비었다.

> 장소 상세 화면에서 설명이 보이던 것은 우리 DB 가 아니라 **프론트가 패스스루
> `GET /api/places/common?contentId=` 를 직접 불러서**였다. 그래서 관광API contentId 가 없는
> **카카오 출처 장소는 상세에서도 설명이 없었다.**

**고친 것**
- `PlaceImageService` — 대표 이미지 저장·조회 단일 창구
- `Place.ofTourApi(..., description, ...)` + `fillDescriptionIfBlank`
- `PlaceBackfillBatch` — 기존 행용 백필. `detailCommon2`(사진+설명) → `detailImage2`(갤러리)
- `PlaceholderImages` — 관광API 가 모르는 장소는 분류별 기본 이미지. **DB 에 저장하지 않고 응답에서만** 끼운다

### 2-2. 카카오 식당·카페가 루트에 못 담기던 문제 🔴

확정 경로가 관광API 하나뿐이라 카카오 place id 로는 `detailCommon2` 가 항상 0건 →
고르는 족족 "관광API 에서 장소를 찾을 수 없습니다".

**고친 것**: `KakaoPlaceImporter` 추가. 카카오는 id 단건 조회가 없어서, 받은 이름·좌표로
검색한 뒤 **id 가 일치하는 결과만** 채택한다(저장값은 전부 카카오 응답에서 온다).

**추가 폴백**(2026-09-18): `source` 가 안 와도 관광API 에서 못 찾고 이름·좌표가 있으면
카카오로 재시도한다. 프론트 어느 한 화면에서 `source` 만 빠져도 통째로 막히던 문제가 있었다
(「윤군커피 옥련점」 카카오 id `1292635388` — 10자리, 관광API contentId 는 6~7자리).

### 2-3. 촬영지를 1곳만 골라도 관련명소가 2곳 들어감

`RoutePlanner.java` 의 `target = Math.min(MAX_RELATED_SPOTS, allSpots.size())` 가
사용자 선택 개수를 안 봤다. 덕혜옹주에서 덕수궁만 골라도 창덕궁 낙선재가 `SCORED` 로 붙었다.

**고친 것**: `relatedSpotTarget(userPickedCount, anchorCount)` 로 분리. 고른 게 있으면 그 개수,
없을 때만 `MAX_RELATED_SPOTS`. 테스트 `RelatedSpotTargetTest`.

### 2-4. "루트 변경하기" 가 고른 촬영지를 지움

프론트는 직전 루트를 통째로 `exclude_place_ids` 로 보내는데 `spot_place_ids` 와 반드시 겹친다.
`anchorsAfterExclusion` 이 제외를 먼저 적용해 고른 앵커가 `byId` 에서 사라졌다.
광해에서 창덕궁을 고르고 변경하기를 누르면 종묘로 바뀌었다.

**고친 것**: `excludeWithoutUserPicks` 로 제외 목록에서 `spot_place_ids` 를 먼저 뺀다.
`RoutePlanRequest` javadoc 이 원래 그렇게 적고 있었으니 코드가 문서를 안 지킨 쪽이었다.
테스트 `ExcludeWithUserPicksTest`.

### 2-5. 추천 일정 404 (공개 88편 중 62편)

`ItineraryService.recommend` 가 `content_place` 만 직접 읽었다. 반면 `RoutePlanner` 는
`ContentAnchorResolver` 로 **인물 체인**(`content_person → place_person`)까지 본다.
그래서 같은 작품이 `/route` 는 되고 `/recommend` 는 404 였다.

**고친 것**
- `recommend()` 가 `ContentAnchorResolver` 를 쓴다 → **코드만으로 22편 해소**
- 장소가 0곳이어도 **200 + `anchor_source: "NONE"`** 로 내려보낸다. 404 는 이제 "콘텐츠 자체가 없음" 일 때만

### 2-6. 시드 생성기 버그

`seed-content-places.ps1` 의 `build-sql` 이 `FROM content c WHERE c.content_id = ...` 가드를
만들었는데 `content` 의 PK 는 **`id`** 다. 그대로 실행하면 첫 줄에서 스크립트 전체가 죽는다.

### 2-7. 관광API 키 2건

**① 호출한도 초과 (429)** — 사진 백필을 만들면서 295곳 × 최대 5회로 한도를 넘겨
`LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR` 가 34건 났다. 그동안
`locationBasedList2` 가 빈 목록을 돌려줘 **후보가 전부 카카오로만** 채워졌고 `detailCommon2` 도
실패해 장소 확정이 깨졌다. → 새 키로 교체.

**② 연관 관광지 403** — 공공데이터포털은 **데이터셋 단위로 활용신청**을 받는다. 국문 관광정보
(15101578)와 연관 관광지(15128560)를 다른 계정에서 신청해 키가 갈렸고, 한쪽 키로 다른 서비스를
부르면 403 이다. → `PublicDataClient` 가 (URL, 키) 짝을 서비스별로 들고 `get` / `getRelated` 로
나눈다. `TAR_RLTE_API_KEY` 를 비우면 `PUBLIC_DATA_API_KEY` 를 그대로 쓴다.

### ⚠️ PR #58 (`content_place` 유무로 콘텐츠 노출 게이팅)과의 충돌

`AnchorDiscoveryBatch` 가 이렇게 판정한다:

```java
boolean hasPlaces = !contentPlaceRepository
        .findByIdContentIdOrderByRecommendOrderAsc(content.getId()).isEmpty();
if (hasPlaces) { content.publish(); } else { content.markPending(); }
```

**`content_place` 만 보고 `PENDING`(비노출)으로 내린다.** 그런데 `recommend()` 와 `RoutePlanner` 는
`ContentAnchorResolver` 로 **인물 체인**(`content_person → place_person`)까지 본다.
현재 `content_place` 없이 인물 체인만으로 일정이 나오는 작품이 **17편**이다
(간신·명량·왕의 남자 등).

**이 배치를 돌리면 그 17편이 전부 숨겨진다** — 멀쩡히 동작하는 작품인데도. 88편 → 71편이 된다.

배치는 수동 실행(`POST /api/admin/route/discover-anchors`)이라 아직 반영되지 않았다.
고치려면 저 판정을 `ContentAnchorResolver.resolve(...).isEmpty()` 로 바꾸면 된다
(`recommend()` 에 한 것과 같은 수정). **작성자와 조율이 필요해 임의로 건드리지 않았다.**

## 9. 참고 — 관광API 발급/확인

| | |
| --- | --- |
| 국문 관광정보 (KorService2) | <https://www.data.go.kr/data/15101578/openapi.do> |
| 연관 관광지 (TarRlteTarService1) | <https://www.data.go.kr/data/15128560/openapi.do> |
| 키 확인 | 마이페이지 → 데이터활용 → Open API → **인증키 발급현황** |
| 사용량 확인 | 마이페이지 → 데이터활용 → Open API → **활용신청 현황** (일일 트래픽/잔여) |

- **서비스마다 따로 활용신청**해야 한다. 한쪽 키로 다른 서비스를 부르면 403
- 인증키는 Encoding/Decoding 두 형태로 보이는데 **어느 쪽을 넣어도 동작**한다
  (`TourApiClient.decodeIfEncoded` 가 `%` 유무로 판단해 정확히 한 번만 인코딩)
- 연관 관광지는 `baseYm` 이 **필수**. 서버 기본값 `202503`. 데이터 제공 기간이
  2024-05~2025-04 이라 범위 밖(`202404` 등)은 0건이 나온다
