## 3. 다음에 할 일 (사용자가 원하는 것)

### 3-1. ⭐ 지도에 타원 그리고 그 안에 식당 띄우기 — 최우선

사용자 표현: *"1장소와 2장소, 그 사이에 타원 범위로 식당이 뜨게. 위치 보고 여기서 먹어야겠다 하기 좋게."*

**백엔드는 이미 다 돼 있다. 프론트 렌더링만 남았다.**

`POST /api/itineraries/route` 응답의 `segments[]` 가 타원 재료를 전부 준다:

```jsonc
{ "segment_index": 0,
  "start_place_id": 174, "end_place_id": 181,
  "start_latitude": 34.88, "start_longitude": 128.69,   // 초점 A
  "end_latitude": 34.90,  "end_longitude": 128.71,      // 초점 B
  "direct_distance_m": 2450,      // 두 초점 사이 거리 = 2c
  "allowance_meters": 3000,       // 허용 우회거리
  "partial_coverage": false,
  "slot_orders": [1, 2] }         // 이 구간에서 채울 칸들의 visit_order
```

**타원의 정의**: `d(A,P) + d(P,B) <= d(A,B) + allowance` 인 점 P 의 집합.
서버의 `DetourFilter` 가 후보를 거를 때 쓰는 식과 정확히 같다. 즉 화면에 그리는 타원과
후보 목록이 일치한다.

**카카오맵 SDK 에는 타원 도형이 없다.** `kakao.maps.Polygon` 으로 근사한다:

```js
// 장반경 a = (d + allowance) / 2,  초점거리 c = d / 2,  단반경 b = sqrt(a² - c²)
// 중심은 A·B 의 중점, 장축은 A→B 방향
function ellipsePath(aLat, aLng, bLat, bLng, allowanceM, steps = 72) {
  const R = 6371000, toRad = Math.PI / 180;
  const midLat = (aLat + bLat) / 2, midLng = (aLng + bLng) / 2;
  const mPerDegLat = 111320;
  const mPerDegLng = 111320 * Math.cos(midLat * toRad);

  // 미터 평면으로 바꿔서 계산 (수 km 범위라 오차 무시 가능)
  const dx = (bLng - aLng) * mPerDegLng, dy = (bLat - aLat) * mPerDegLat;
  const d = Math.hypot(dx, dy);
  const a = (d + allowanceM) / 2, c = d / 2;
  const b = Math.sqrt(Math.max(0, a * a - c * c));
  const theta = Math.atan2(dy, dx);          // 장축 방향

  const path = [];
  for (let i = 0; i <= steps; i++) {
    const t = (2 * Math.PI * i) / steps;
    const ex = a * Math.cos(t), ey = b * Math.sin(t);          // 축 정렬 타원
    const rx = ex * Math.cos(theta) - ey * Math.sin(theta);    // 회전
    const ry = ex * Math.sin(theta) + ey * Math.cos(theta);
    path.push(new kakao.maps.LatLng(midLat + ry / mPerDegLat, midLng + rx / mPerDegLng));
  }
  return path;
}

new kakao.maps.Polygon({
  path: ellipsePath(seg.start_latitude, seg.start_longitude,
                    seg.end_latitude, seg.end_longitude, seg.allowance_meters),
  strokeWeight: 2, strokeColor: '#2563eb', strokeOpacity: 0.6, strokeStyle: 'dash',
  fillColor: '#2563eb', fillOpacity: 0.07
}).setMap(map);
```

그 위에 `GET /api/itineraries/route/candidates` 결과를 핀으로 뿌린다. 후보에 `latitude`/`longitude`
가 있고 `detour_meters` 오름차순으로 정렬돼 온다.

주의할 점:
- `end_place_id` 가 없는 **꼬리 구간**(하루 마지막)은 타원이 성립하지 않는다. 앵커 중심 원으로 그린다.
  이때 `detour_known: false` 이고 `detour_meters` 는 우회거리가 아니라 앵커로부터의 거리다.
- `partial_coverage: true` 면 두 명소가 멀어 타원 중앙부를 검색하지 못한 경우다. 사용자에게 알려야 한다.
- 허용거리 슬라이더를 움직이면 타원과 후보가 함께 바뀐다. **디바운스 필수** — 서버에 캐시가 없다.

`tools/route-test.html` 에 지금은 마커와 직선만 있다. 위 함수를 넣으면 바로 확인된다.

### 3-2. "위치가 1개만 뜬다" 문제 — 급함

사용자가 화면에서 겪은 증상. 원인을 운영에서 확인했다.

| 작품 | `GET /contents/{id}/places` | `GET /itineraries/recommend` | `POST /itineraries/route` |
| --- | ---: | ---: | ---: |
| 스윙키즈 | 1곳 | 1개 | **3곳** |
| 광해 | 0곳 | **404** | **3곳** |

앞의 두 엔드포인트는 **`content_place` 테이블만** 본다. 오늘 만든 인물 체인 폴백과 일반 명소 보충은
`POST /route` 에만 들어가 있다. 기존 문서에 "No.27 과 병존 중, 프론트가 어느 걸 쓸지 정해달라"고
미해결로 남아 있던 항목이 증상으로 드러난 것이다.

해결 방법:
- **A.** 프론트가 `POST /route` 만 쓰게 한다 (백엔드 작업 0)
- **B.** `GET /contents/{id}/places` 에도 `ContentAnchorResolver` 를 적용해 인물 체인까지 보게 한다 (백엔드 30분)
- **C.** 둘 다

B 를 하면 `content_place` 가 0행인 22편이 "관련 장소 없음"으로 보이는 것도 함께 해결된다.

### 3-3. 식당·카페 후보를 카카오맵처럼 보여주기

사용자 요청. 카카오 로컬 API 가 실제로 주는 것을 확인했다.

| 항목 | 제공 | 지금 응답에 |
| --- | --- | --- |
| 상호명·카테고리 | 있음 | 있음 |
| 전화번호 | 있음 | **없음 — 추가 필요** |
| 도로명 주소 | 있음 | **없음 — 추가 필요** |
| `place_url` (`place.map.kakao.com/{id}`) | 있음 | **없음 — 추가 필요** ⭐ |
| 사진 | **없음** | TourAPI 출신만 `image_url` 로 있음 |
| 별점·리뷰 | **없음** | 불가 |
| 영업시간 | **없음** | TourAPI 출신만, `places/import` 후 |

**별점·리뷰·사진은 카카오 로컬 API 로 못 가져온다.** 대신 `place_url` 을 노출하면 사용자가
카카오맵 장소 페이지에서 전부 볼 수 있다. `CandidateView` 한 파일에 3개 필드를 더하면 된다(30분).

### 3-4. 작품 숨김이 목록에 반영되지 않음

관련 명소 0곳인 40편이 `GET /api/contents` 목록에 그대로 나오고 루트만 404 다.
`route_status` 같은 필드가 코드에 **없다**(검색 0건). 프론트가 사전에 거를 방법이 없다.
목록 응답에 `route_available` 플래그를 넣는 것이 가장 간단하다.

## 4. 알려진 한계 (고치지 않고 남긴 것)

- **일반 명소가 거리순으로만 뽑힌다.** 관광 가치 필터가 없어 `동대문 닭한마리 골목`,
  `인천업사이클에코센터`, `신석구 사택 터` 같은 곳이 코스에 들어온다.
  TourAPI 대표이미지(`firstimage`) 유무 등으로 거를 수 있다.
- **방문 순서가 운영시간을 보지 않는다.** `VisitOrderOptimizer` 는 동선만 본다.
  하루 시작을 09:00 으로 당기고 카페 체류를 40분으로 줄여 완화했을 뿐이다.
  근본 해결은 순서 후보 중 마지막 칸이 그 시각에 열려 있는 것을 우선하도록 고치는 것.
  `SpotScorer` 의 `night-weight` 를 0.4 로 올렸으나 **효과가 없었다** — 마지막 칸을 정하는 것은
  SpotScorer 가 아니라 VisitOrderOptimizer 이기 때문이다.
- **루트 결과 캐시가 없다.** 같은 작품을 여러 번 부르면 매번 외부 API 를 호출한다.
- **식당·카페를 고른 뒤 전체 동선이 재계산되지 않는다.** 개별 타원 조건만 통과했을 뿐이다.
- **운영 `JWT_SECRET` 이 빈 값이다.** GitHub Secret 은 등록돼 있는데 서버 `.env` 에는 비어 있다.
  로그인이 실제로 되는지 확인이 필요하다. 이 파트와 무관한 별건.

## 5. 다음 세션이 주의할 것

### 권한으로 막히는 작업

이 세션에서 아래가 차단됐다. 우회하지 말고 사용자에게 명령을 넘겨야 한다.

| 작업 | 차단 사유 |
| --- | --- |
| 운영 DB 쓰기(`INSERT`/`COMMIT`) | `Modify Shared Resources` |
| 운영 DB `ALTER TABLE` | `Production Deploy` |
| 서버에 파일 전송(`scp`) | `Remote Shell Writes` |
| 서버 `.env` 에서 키 값 읽기 | `Credential Materialization` |

읽기 질의와 `BEGIN … ROLLBACK` 검증은 허용된다. **적재 SQL 은 만들어 두고 사용자가 실행하는
방식으로 진행했다.** `scripts/load-anchors-*.sql`, `scripts/load-rediscovered.sql` 이 그 결과물이고
전부 멱등이다.

### DB 스키마 주의

`place_source_check` 제약이 `('SEED','TOUR_API')` 만 허용하고 있었다. `KAKAO` 를 추가하는
`ALTER` 를 운영에 적용했으나, **`ddl-auto: update` 는 기존 CHECK 제약을 갱신하지 않으므로
새 환경에서 재발한다.**

```sql
ALTER TABLE place DROP CONSTRAINT place_source_check;
ALTER TABLE place ADD CONSTRAINT place_source_check CHECK (source IN ('SEED','TOUR_API','KAKAO'));
```

마이그레이션 도구(Flyway 등) 도입을 검토할 것. 현재 프로젝트에 없다.

### 배포

`dev` 에 병합하면 자동 배포된다(4~8분, 수십 초 중단). 배포 후 확인할 것:

```powershell
# road_verified 가 true 로 나오면 KAKAO_MAP_REST_KEY 가 제대로 주입된 것
python -c "..."   # scripts/route-sweep.py https://api.itda-travel.com 를 쓰는 편이 낫다
```

새 환경변수를 추가할 때는 **세 곳을 모두** 고쳐야 한다. 오늘 한 곳을 빠뜨려 기능이 조용히 꺼졌다.
1. GitHub Secrets 등록
2. `.github/workflows/deploy.yml` 의 `env:` 와 `envs:` 목록과 `.env` 생성 블록
3. **`docker-compose.yml` 의 `environment:` 블록** ← 여기를 빠뜨렸다
